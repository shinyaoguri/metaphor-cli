# 0005: 共有セッション — `mcp` は `watch` にアタッチする観測クライアントにする

- **状態**: 採用 (2026-06-22)

- **文脈**: 人間 (VSCode + `metaphor watch`) と AI (Claude Code 経由の `metaphor mcp`) が同じスケッチを触るとき、`mcp` は**自前で子プロセスを spawn していた**。結果、人間が見ている絵と AI が観測している絵が別インスタンスになる。同じ `.build` を 2 つのプロセスが奪い合うロック競合も起きる。

  素直な解決は「`mcp` が動作中の `watch` にアタッチする」ことだが、**stdio 型の MCP サーバは別プロセスへアタッチする口を持たない**。プロセス間で状態を共有する手段を自前で用意する必要があった。

  一方、編集の共有は考える必要が無い。人間も AI もディスクにファイルを書き、`watch` がそれを検知して再ビルドする — **編集はファイルシステムが既に共有している**。MCP に残る役割は観測だけになる。

- **決定**: 役割を**所有者 = `watch` / `mcp` = アタッチする観測クライアント**に分離し、既存の Probe ファイル IPC (`.metaphor/`) を拡張して繋ぐ。

  - `SharedSession` が `.metaphor/session.json` (所有者 pid + manifest) と `.metaphor/build-status.json` を扱う。書き込みはアトミック (`.tmp` → rename)、生存判定は pid で行う
  - `watch` は起動時に manifest を書き、毎ビルドで build-status を更新し、停止時に manifest を消す。ビューアあり / `--no-viewer` のどちらでも Probe を既定 ON にして子を観測可能にする (`--no-probe` で opt-out)
  - `metaphor mcp` は起動時に生存セッションがあれば**アタッチし、spawn もビルドもしない**。無ければ従来どおり自前で起動する
  - `metaphor` ライブラリ側の改修は不要

- **影響**: ビルドの所有者が `watch` 1 つになり、`.build` のロック競合が消えた。AI が `snapshot` で見る絵は人間が見ている窓と同一インスタンスになる。

  代わりに**起動順序が意味を持つようになった**。`mcp` はアタッチするか自前起動するかを**起動時に 1 度だけ**判定するので、`watch` より先に Claude Code を立ち上げると、以降ずっと別のヘッドレスインスタンスを観測し続ける。復旧は `/mcp` の再接続か開き直し。この落とし穴は README に明記してある (#29)。

  アタッチ時の `input` は当初未対応 (Phase 2 へ送り)、`snapshot` は直近のビルドが失敗しているときに注記を返す。

  `.metaphor/` がプロセス間の待ち合わせ場所になったことで、**その置き場が親子で一致していることが前提条件**になった。これは後に `.app` 起動で cwd が `/` になる形で破れ、[ADR 0008](0008-state-dir-absolute.md) につながる。
